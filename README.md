# ai-bot-shops

Shop drivers for [AI-Bot](https://github.com/davideditelabs/ai-bot): one small program per online shop that answers "which products
does this shop have for this word?". A bot on any AI-Bot server can use a driver from here instead of learning the shop from scratch.

This repository is **public and holds no personal data**: no logins, cookies, addresses, baskets, orders, names or search history, and no
recorded pages. Only code that reads a shop's public search and product pages. See [CONTRACT.md](CONTRACT.md) for the exact rules
(contract version 1).

```
CONTRACT.md      the versioned driver contract
templates/       starters: shopify, magento, woocommerce, prestashop, maf, json-feed, html
shops/<domain>/  one folder per shop: driver.json, index.mjs (+ PROVENANCE.json, RESULT.json)
tools/           check.mjs, probe.mjs, index.mjs (plain Node 20+, no dependencies)
index.json       the catalogue, generated by tools/index.mjs
test/            node:test tests for the tools
```

## How the builder uses it

1. A user's bot asks for a shop it has no driver for. The AI-Bot gate looks in this library first (a shallow clone it keeps, fetched on
   start, daily and on a miss). If `index.json` lists the domain and the driver is not marked `broken`, the gate stages the two driver
   files, runs its own static scan, and **proves the driver live on the real shop** before any bot uses it. Library code is never trusted
   without that proof.
2. If the shop is not here, a build job writes a driver (from a starter in `templates/` or from scratch), runs `tools/check.mjs` and
   `tools/probe.mjs` itself, and opens **one pull request that touches only `shops/<domain>/`**, with a `RESULT.json` saying what happened.
3. CI runs the checks. The nightly merger merges the PR when CI is green, the builder's own server recorded the driver as learned, and
   `hosts` lists only the shop's own domain. Anything else waits for a person.
4. `index.json` is regenerated from `main` (`node tools/index.mjs`); a nightly run can mark drivers that stopped working with a
   `broken.json` (`["celeiro.pt"]` or `{ "celeiro.pt": "search answers 404" }`).

`main` is protected: changes arrive by pull request and need the `check` CI job to pass.

## Adding a shop

```sh
cp -r templates/shopify shops/celeiro.pt        # pick the starter that fits; or write index.mjs yourself
# edit shops/celeiro.pt/driver.json and index.mjs: domain, name, hosts, ORIGIN, the shop's own fields
node tools/check.mjs shops/celeiro.pt           # shape, static scan, forbidden pages, size, no personal data
node tools/probe.mjs shops/celeiro.pt           # live search with a common word, shape of the products
```

Open a pull request with only `shops/celeiro.pt/` changed. The probe word is always a common word from the list in CONTRACT.md, never
something a user shops for.

## The tools

All plain Node 20+ ES modules; nothing to install. CI uses Node 22.

| command | does |
| --- | --- |
| `node --test` | runs the tests (the network is always a stub in tests) |
| `node tools/check.mjs [shops/<domain> ...]` | checks the folders (no arguments: every folder in `shops/`; an empty `shops/` passes). Lists every problem with a plain-language fix. `--json` prints data, including `ownDomainOnly`. Exit code 1 on any problem. |
| `git diff --name-only origin/main...HEAD \| node tools/check.mjs --diff-names` | a pull request may touch `shops/<one-domain>/**` and nothing else |
| `node tools/probe.mjs shops/<domain> [--word w] [--json]` | runs the driver's search against the live shop in a sandboxed Node process, with the gate's `http()` limits (own hosts, https, GET/HEAD, no forbidden pages), and validates the products |
| `node tools/index.mjs [--out index.json] [--broken broken.json] [--commit sha] [--stdout]` | writes `index.json`: domain, name, hosts, contract version, actions, sha256 of each file, `ownDomainOnly`, `broken`. Deterministic. |

`check.mjs` never repeats a matched e-mail, number or token in full in its report, because CI logs are public.
